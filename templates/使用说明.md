# 用小说素材生成角色卡 / 场景卡 / 信息库

## 三步走

**第一步：把模板和素材一起交给大模型**

复制 [角色卡模板.md](角色卡模板.md)、[场景卡模板.md](场景卡模板.md) 或 [信息库模板.md](信息库模板.md) 的**全文**，连同你的小说素材（原文片段即可，越长越准），一起发给任意大模型，并附一句话：

> 请严格按这份模板的填写说明，依据下面的小说素材填写。保留所有【】字段名与结构，不要输出 JSON，不要编造素材里没有的内容。

**第二步：检查填写结果**

- 字段名是否原样保留（`【姓名】` 这类）；
- 台词样例是否是**原句**（不是模型改写的）；
- 权重是否是 0~1 的小数；
- 场景卡的【出场角色】是否都是**已有角色卡**的姓名；
- 信息库的每个条目名是否**互不相同**、是否含 `\ / : * ? " < > |`（条目名会成为文件名）。

**第三步：导入库中**

两个入口：装好的应用里用**界面导入**（见下；装包版没有命令行）；**源码检出**（`git clone` 后的 `app/` 目录）里用下面这几条命令：

```bash
python -m harness.tools.import_cards ../templates/填好的角色卡.md          # 角色卡 → app/characters/
python -m harness.tools.import_cards ../templates/填好的场景卡.md          # 自动识别类型
python -m harness.tools.import_cards ../templates/填好的信息库.md          # 信息库 → app/libraries/
python -m harness.tools.import_cards 某文件.md --dry-run                  # 只看解析结果，不写盘
python -m harness.tools.import_cards 某场景.md --name 深夜小馆.json         # 指定场景文件名
python -m harness.tools.import_cards 某文件.md --force                    # 覆盖同名旧文件/旧库
python -m harness.tools.import_cards 某库.md --libraries-dir 别处/libraries # 换一个信息库根
```

也可以**在应用里导入**：「场景」或「角色」菜单 →「角色/场景库…」→ 底部「从模板导入…」，
选一个填好的 `.md` 即可；导入结果（含「哪些字段没填、已用默认值」）会当面告诉你。

导入成功后，角色/场景会出现在应用的「角色」「场景」菜单的库里，可直接选用。

> **信息库（源码检出下）请优先用上面的命令行导入**（`--libraries-dir` 缺省就是 `app/libraries/`，也就是
> 引擎真正会去读的那个根）。应用的导入对话框是**角色/场景**那套界面里长出来的，对信息库
> 有两处不到位，本期界面还没跟上：**① 类型会显示成「角色卡」**（它其实进了 `app/libraries/`，
> 角色菜单里不会多出一张卡，别去那里找）；**② 库根按「角色卡所在目录的兄弟目录 `libraries/`
> 推导」**——角色卡只有装在 `app/characters/` 时才是 `app/libraries/`，若你用的是自定义卡目录，
> 导进去的库会落在引擎不读的地方（症状是"导入了，角色却永远不知道任何事"，界面不报错）。

## 信息库模板怎么填

信息库 = 一个角色（或整个世界）**记得的东西**。一份模板描述**一个库**，它由三样东西构成：

| 字段 | 填什么 |
|---|---|
| 【库名】 | 必填。这个库叫什么，如 `庆国世界观`（写不写书名号都行） |
| 【类型】 | 必填。`广域库` = 世界观/设定，所有角色都能订阅；`角色库` = 某一个角色自己的知识库 |
| 【归属角色】 | 【类型】填「角色库」时**必填**（写角色卡里已有的姓名）；广域库留空 |
| 【订阅】 | 可选，一行一个库名。表示这个角色的索引里还要挂上别处的入口，对方一改他立刻看到 |
| 【条目 N 名称】 | 必填（至少一条）。会成为条目的**键**，也是磁盘上的文件名 |
| 【条目 N 摘要】 | **一行**，是角色"扫一眼就知道要不要读"的全部依据，写得值不值钱直接决定好不好用 |
| 【条目 N 正文】 | 正文。可以多行——**一直写到下一个字段行**（`【条目…】` 或 `【库名】` 这类库信息字段）为止；中间的小标题、`---` 分隔线、`【…】：`、`[[另一个条目的名称]]` 都是**内容**，原样保留（指不到东西不会报错，只是那条链接走不通） |
| 【条目 N 主题】 | 可选，仅用于索引显示时归拢（`地理` / `人物` 这类），不构成层级，库是图不是树 |
| 【条目 N 进索引】 | `是`（默认）= 列进索引表；`否` = 只藏在图里，顺着别人的 `[[链接]]` 才摸得到（图里那些"要顺藤摸瓜才知道"的秘密就该这么写） |

一条条目就是 `名称 / 摘要 / 正文 / 主题 / 进索引` **五行一组**；要更多条目就把这一组往下复制，
编号写 2、3…（编号写错或忘了改只是提示，不影响导入——**名称**才是分组的分界）。

**导到哪去了**：广域库落在 `app/libraries/wide/<库名>/`，角色库落在
`app/libraries/characters/<归属角色>/`——注意是**归属角色**（引擎按角色名找库），
`【库名】`只是显示名。库里每条条目是一个 `<条目名>.md`（front-matter + 正文，条目文件的
唯一真相源），`library.json` 只存库名/类型/归属角色与**索引顺序**；你可以直接手写 `.md`
丢进 `entries/`，下次打开就被收录。导入是**新的库**才写盘；库已存在时加 `--force` 覆盖，
没被模板列出的手写条目会**原样保留**并在报告里告诉你（绝不静默删你的东西）。

两条边界（都会被当场拦下并说清原因，不会"报成功却丢了东西"）：

- 模板里的条目名与库里**没被模板列出**的既有条目**只差大小写**时（`ABC` 与 `abc` 在
  Windows 上是**同一个文件**），覆盖导入会被拒绝——请改个名字再导，否则就是把人家那条
  手写记忆顶掉；
- 库的位置若是被一个**同名文件**占着（手工放错文件、上次写入中断），也会拒绝并告诉你
  该把哪个文件移开（不会甩一串系统报错给你）。

**正文怎么写才不丢内容**：正文一路写到下一个 `【条目…】` 字段为止，中间的小标题、
`---`、`【…】：` 都原样保留——**唯一要避开的是「`【条目 …】` 形状的行」**：它长得就是
条目字段的样子，程序会把它当成新字段（比如正文里写一行 `【条目 2 名称】：乙`，就会多出
一条空条目）。要强调什么就写成别的样子（`**条目 2 名称**`、`【条目 2 名称】`不带冒号 都行）。

## 要点

- **一个模板一个对象**：素材里有多人/多场景时，让模型**复制模板逐一填写**，不要塞进一份。
- **素材越聚焦越准**：与其给整本书，不如给最能体现这个角色说话方式与处境的几段。
- **语料是灵魂**：【语言风格】【思维方式】【台词样例】决定角色像不像原著，值得多花时间打磨。
- **权重不必纠结**：拿不准就用模板给的建议区间中值，之后可以在应用的场景/角色编辑器里随时调。
- **解析失败怎么办**：导入器会明确指出**哪个字段、什么问题**（不是笼统报错）。照着改那一个字段再导入即可。
