# 多智能体角色扮演系统 — 设计文档

> **摘要**：本文是这套多角色会话引擎的**设计基准（语义来源）**，代码注释与其余文档中统称「设计文档」（即本文件 `docs/design.md`）。本文汇总了「自定义 harness，让多个角色 agent 在场景中自主交互」这一构想的完整讨论结论：核心原则、三循环架构、各模块 schema、块级竞价调度模型、信息边界、成本策略与开放问题。它是「为什么这样设计」的出处，**不是**行为现状的唯一依据（现状以 README 为准）。
>
> **对应代码**：`app/src/harness/schemas.py`（三张 schema 与 ThinkResult）、`dynamics.py`（w1~w7 数值 bid 与情绪衰减）、`bidding.py`（块级竞价仲裁）、`visibility.py`（可见性投影）、`memory.py`（私有记忆）、`prompters.py`（think/speak 提示词）、`graph.py`（LangGraph 图与节点）、`engine.py`（高层引擎）。
>
> **读者与顺序**：想理解设计意图的人从这里开始；落地与版本细节见 `docs/technical-scheme.md`；开发过程记录见 `docs/implementation-plan.md`；界面与场景自由度见 `docs/ui-and-scene-freedom.md`。文中的角色示例一律取公有领域演示角色（福尔摩斯 / 华生 / 贝克街221B），与引擎实现无关。

## 1. 项目愿景与目标

**目标**：搭建一个**自定义 harness**（不依赖 Claude Code 的 subagent 机制），让多个「角色 agent」在场景中自主交互。

**动机**：Claude Code 下的 subagent 无法实现真正的角色交互，因为：
- 子代理之间**没有 peer-to-peer 通道**，只有 hub-and-spoke（主代理中转）
- 子代理**无共享记忆**，每次派生都是全新上下文
- 交互只能靠主代理手动转述，token 昂贵、叙事破碎

**核心突破点**：把「信息边界」从**软约束**（靠 prompt 求角色「假装不知道」，会漏）升级为**硬约束**（数据访问控制——不给角色看的东西，直接不进它的输入）。

**应用范围**：不局限于写小说，可用于任何需要真实角色扮演 / 社会模拟的场景。

---

## 2. 核心设计原则

1. **内心状态私有**：角色的情绪、目标、动机是私有的，别人只能通过外在行为推测，不能读取。
2. **在场 ≠ 认知**：「谁在这个场景里」与「谁知道什么」是两条**正交轴**，必须分开建模。
3. **信息边界 = 数据访问控制**：不该知道的信息，直接不出现在该角色的输入里，而非请求它「装不知道」。
4. **涌现式调度**：谁说话由各角色基于自己的心理状态**自己算出来**，不是中央导演微操。
5. **边界是「世界规则」，不是导演拍板**（diegetic）：场景收束要有世界内的理由（打烊、车来了），而非导演硬掐。

---

## 3. 总体架构

系统由**三个循环** + **一个世界规则层**组成：

```
┌─────────────────────────────────────────────┐
│  感知环 (perceive)  权衡环 (deliberate)  行动环 (act)  │
│   ─────────────────────────────────────────  │
│  世界规则层：场景 / 硬边界 / 事件注入 / 对话圈        │
└─────────────────────────────────────────────┘
```

- **感知环**：每个听众对上一句话做解释，更新自己的私有状态。
- **权衡环**：从更新后的状态计算 urge（发言冲动），决定说/不说。
- **行动环**：当前发言者生成一句话（块）。
- **世界规则层**：管理场景状态、注入世界事件、在硬边界到达时收束。

这是经典的 **sense–think–act** 循环，被特化成了社交话轮系统。

## 4. 消息 schema

把传统 LLM 的 `{用户, llm}` 消息流，扩展为**带说话者、带可见性、带在场信息**的消息流：

```json
{
  "id": 12,
  "speaker": "福尔摩斯",
  "speaker_type": "character",
  "content": "……",
  "in_scene": "贝克街221B",
  "knows": ["福尔摩斯", "华生"],
  "reply_to": 9,
  "address": "华生",
  "turn": 3
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `speaker` | 谁说的 |
| `speaker_type` | `character` / `director` / `narrator` / `human` / `system` |
| `content` | 内容 |
| `in_scene` | 在哪个场景（**在场轴**）。注：早期设想的「对话圈」已在后续版本整体删除，在场轴退化为场景本身——一条消息要么属于本场景、要么不属于 |
| `knows` | 谁可见此消息（**认知轴**，缺省=全员可见） |
| `reply_to` | 回复哪条，构成对话图而非线性流 |
| `address` | 冲谁说（邻接对/点名） |

**关键**：`in_scene`（在场）和 `knows`（认知）是两条正交轴，必须拆开。在场决定「谁**能**参与」，认知决定「参与者**能说什么**」。混淆二者会让调度与保密互相污染。

## 5. 角色卡 schema（含心理权重 w1~w7）

每个角色 agent 的定义文件，即它的 system prompt + 参数：

```json
{
  "name": "福尔摩斯",
  "personality": { "描述": "……" },
  "abilities": ["演绎推理"],
  "relationships": { "华生": "室友与记录者" },
  "knowledge_boundary": ["只知道自己经历和被告知的事"],
  "weights": {
    "w1_relevance": 0.5,
    "w2_arousal": 0.9,
    "w3_adjacency": 0.7,
    "w4_goal_pressure": 0.6,
    "w5_talkativeness": 0.9,
    "w6_inhibition": 0.05,
    "w7_scene_pressure": 0.5
  },
  "emotion_decay_rate": 0.4
}
```

**关键设计**：心理权重 w1~w7 把「性格」量化成了调度参数。举例如下：

| 角色 | 特征 | 权重表现 |
|---|---|---|
| 福尔摩斯 | 冲动、爱抢话、记仇 | w2 拉满、w6 趋零、衰减慢 |
| 华生 | 冷静、观察多 | w2 低、w6 高 |
| 雷斯垂德 | 被点名/被挑衅才多说 | w5 中等、w3 高 |

**情绪衰减率也是性格参数**：福尔摩斯记仇（慢衰减）、雷斯垂德消气快（快衰减）。否则每条线都让情绪只涨不跌，系统迟早全员顶格、全员抢话。

## 6. 场景 schema

```json
{
  "name": "贝克街221B",
  "participants": ["福尔摩斯", "华生", "雷斯垂德", "哈德森太太"],
  "circles": [
    { "id": "壁炉边", "members": ["福尔摩斯", "华生"] },
    { "id": "窗边", "members": ["雷斯垂德", "哈德森太太"] }
  ],
  "hard_boundary": { "type": "time", "value": "23:00", "desc": "就寝" }
}
```

- 多个对话圈 = 多个独立的调度实例，各自跑竞价。（对话圈已在后续版本整体删除：一个场景只跑一个调度实例，`circles` 字段被静默淘汰，改由入场记录 `characters` 与在场轴 `in_scene` 描述「谁在场」。）
- 角色可在圈间**流动**（`move(from圈, to圈)`，鸡尾酒会效应）。
- `hard_boundary` 是世界规则层的硬约束。

## 7. 调度模型（核心）：块级竞价

### 7.1 话轮降级成「块」

不把「话轮」定义成「一整段话」，而是定义成「**一句话/一个言语动作**」（语言学里的 turn-constructional unit）。这样「打断」就自动涌现——不需要真·流式打断，只需「块足够短 + 块之间重新竞价」，视觉上就等价于被打断。

### 7.2 urge 竞价函数

> **实现口径（2026-09 更新）**：w1~w7 是**系数**，乘的是随情景实时演化的分量；发言权
> 由 harness 按下面的数值公式算出，**LLM 每轮只提供状态增量与一次自评冲动**（不再由
> LLM 自报值直接决定谁开口）。参数集中在 `harness/dynamics.py::DynamicsParams`。

```
bid = w1·相关度        (话题与我多相关；被点名/被提及→升，否则衰减)
    + w2·情绪唤醒      (我现在多上头；think.aroused 混合 + 按 emotion_decay_rate 衰减)
    + w3·邻接触发      (有没有人刚问我/挑衅我；点名抬升，兑现后回落)
    + w4·目标压力      (私有目标推进低→压力高)
    − w6·抑制基准      (性格抑制：社会层级的刹车)
    + w7·场景压力      (公开场景状态 × 我的私有目标)
    + 沉默压力·(0.4+0.6·w5)      # 越久没开口越大；w5 爱说性调制其斜率
    + 待回应压力                  # 被点名后欠的那一次回答，每轮 ×2 直到开口（封顶 64）
    + urge_gain·自报冲动          # LLM 自评 urge（-1~2，**可为负**=自觉不必说）
    − 刚说完惩罚(recency)         # 防同一人连篇
    + ε(确定性噪声)               # 打破严格等值
```

**负冲动**是有意义的一票：think 若判断"别人已替我把话说尽 / 我没有新内容"，应给出负的
自评冲动，这一项会把该角色从话筒竞争中拉下来。`urge_gain` 缺省 0.6，置 0 即退回"纯数值、
完全不看 LLM 自评"的旧口径。

### 7.3 在位者优势 + 打断阈值

正在说话的人天然有「继续说完整段」的权利，所以：

```
speaker 说一个块
  → 更新所有听众状态（effect）
  → 重算所有人的 urge
  → 若 speaker.urge > 其他人最高 urge + 打断阈值：
        speaker 继续说下一块
    否则：
        发言权交给 urge 最高者   ← 「打断」= 丢了重新竞价
```

否则话痨永远抢话、没人能说第二句。

### 7.4 urge 是动态状态，不是纯函数

```
state_{t+1} = state_t + effect(chunk_t)
urge_{t+1}  = g(state_{t+1}, weights)
```

`effect(chunk_t)` 包含：这句子让谁的情绪降了多少、兑现了谁的挑衅/问题、让谁的目标推进了多少。「我想说的说完了吗」就是 `state.goal_pressure` 的一个变量——说完了归零、自然让出话筒。

### 7.5 沉默压力（随时间增长的 urge 项）

```
silence_pressure = ∫ 时间 × (1 − w5_耐沉默度)
```

- 话痨的沉默压力涨得快、急着填空；沉默型的涨得慢、能坦然静坐。
- 本质是 w5 性格参数的另一面，不新增维度。
- 若算完 urge 后**没人超过开口阈值** → 场子安静（尴尬的沉默是真实的）。连续 K 个块没人开口 → 导演注入事件（侍者加水、电话响了、换话题），或收束场景。

### 7.6 场景压力（w7）

```
urge += w7 · scene_pressure(公开场景状态, 我的私有目标)
```

拆成「公开 × 私有」：
- **公开场景状态**（几点了、快打烊了、谁刚进门）→ 由 harness/世界层注入，因为大家都能看到。
- **我的私有目标**（我还没问她那个问题）→ 只存自己的 state。

「10 点打烊」这个公开事实 + 「我还有话没问」这个私有目标，才合出「快 10 点了，我非说不可」的冲动。**公开的归世界，私有的归角色**。

---

### 7.7 待回应压力（被点名即欠一次回答）

```
被点名/被问 → 待回应压力 = pending_base(1.2)
每过一轮仍未开口 → ×pending_growth(2.0)，封顶 pending_cap(64)
该角色一旦开口 → 归零；期间再次被点名 → 轮数计数重置（债不降）
```

理由：只靠邻接抬升，被点名者常抢不过别人的沉默压力，出现"问了半天没人答"。这一项
**不经权重、直接入 bid**，保证被点名者通常 1~2 轮内拿到话筒；封顶避免无限膨胀。

## 8. think / speak 两步模型

### 8.1 两个 LLM 调用

| 步 | 做什么 | 模型要求 |
|---|---|---|
| **speak** | 生成真正的台词 + 文笔 | 强模型、正常 reasoning |
| **think** | 每个听众解释上一句、更新私有状态、输出 urge 自标注 | 轻模型 / 低 reasoning / 小 max_tokens |

**非对称模型分配**：think 和 speak 可以是两档。同一模型开低推理，或换便宜小模型做 think。

### 8.2 听众侧解释是必要的

只有发言者调整、听众不调整，就没有「反应」，对话就是各说各话的独白拼贴。**每个听众在收到新的一句话时，都要做一次简短思考**，在这次思考中解释这句话、更新自己的状态，最后输出 urge 自标注。

### 8.3 think 步的输出必须锁死格式

「想一下」只有在输出被 schema 锁死时才真的是「短思考」，否则会写成小作文。输出必须是定长结构化 JSON：

```json
{
  "aroused": 0.6,
  "obligation_fulfilled": ["雷斯垂德的追问"],
  "goal_progress": 0.2,
  "addressed": "雷斯垂德",
  "impression_of_speaker": "他今天格外急躁",
  "urge": 0.8
}
```

- `urge` 是**内心状态中唯一被外部消费的数**（作为 bid 的一项加权，见 §7.2）；**可为负**
  ——"别人已替我把话说尽 / 我没新内容"应给负值，把该角色从话筒竞争中拉下来。
- 其余字段是**私有状态**，只进自己的 memory；`aroused/goal_progress/addressed/
  obligation_fulfilled` 还会折进 harness 侧的数值 Dynamics（§7.4）。
- 守住「内心状态私有，只有『要不要说话』这个结论被调度器消费」的原则。

### 8.4 为什么检测交给 LLM 而非启发式

「这句话戳没戳中我的目标、有没有挑衅我」这类判断，交给 LLM 比交给 embedding/正则**稳得多**。启发式/嵌入方案是成本焦虑催生的过度设计。用「轻模型短思考 + 锁格式输出」最简单又准。

## 9. 记忆系统

### 9.1 每个 agent 独立的 memory 文件夹

每个角色 agent 拥有自己的记忆文件夹（类似 Claude Code 的 memory 目录），存：
- 自己的经历、私有目标、情绪状态
- 跨场景持久，不因派生而丢失

### 9.2 「印象」文件夹（Theory of Mind）

每个 agent 维护一个「印象」文件夹，存放**对其他每个人的印象甚至故事**（转眼就忘的路人除外）。

- 这是对「历史上每一次结束了的上下文」的总结。
- 本质是 **Theory of Mind / 信念模型**（接近 BDI：Belief-Desire-Intention 中的 Belief）。
- 角色**只能通过与他人的交互了解对方**，不可能上来就知道对方全部。

### 9.3 think 步是「印象」的写入点

`impression_of_speaker` 字段就是往「我对他的印象」里追加的那一笔。**听一句、判断一次、顺手更新对说话人的印象**，三个动作一次调用全干了，不额外花钱。

## 10. 世界规则层

### 10.1 硬边界（diegetic 收束）

场景收束要有世界内的理由，而非导演拍板：

| 边界类型 | 例子 |
|---|---|
| 时间 | 餐厅 10 点打烊 |
| 物理 | 车来了、雨停了 |
| 社会 | 某人接到电话、主人要先走 |
| 目标完成 | 谈判谈成 / 破裂 |

### 10.2 边界的双作用

边界不只是「终止开关」，还是「逼近时的压力源」：

- 平时：背景。
- 临近：推力（「快 10 点了，我还有话没问」→ urgency 升高，反向喂给 urge）。
- 到点：闸门（不说话也得离场）。

导演要做的，只是在合适时机**注入一个世界事件**，剩下交给规则自然运转。

### 10.3 导演降级为「场景级」

导演**不该逐句调度**，只做三件大事：
1. **开场**（谁在哪、什么情境）
2. **注入事件**（门口进来个人、电话响了）
3. **收束场景**（该切下一幕了）

「谁先说话」这种微观转接，交给涌现式竞价，不归导演管。

## 11. 成本与优化

- **复杂度**：O(N × M)，N 个听众 × M 条话，每条都要 think 一次。
- **当前策略**：think 用轻模型 + 锁格式，单次便宜；speak 才用强模型。
- **后续优化（后话，非现在做）**：注意力门控——只有被「点名/戳中目标/挑衅」的听众才做全量解释，其余走默认衰减。把 N−1 次全量解读砍成「少数相关者的解读」。

## 12. 已收敛的关键决策（决策日志）

| 决策 | 结论 | 理由 |
|---|---|---|
| 一角色一 agent 的用途 | 做「独立核查」绝配；做「互动演戏」不如 inline | 写正文要文笔连贯、戏剧推进 |
| 信息边界实现 | 数据访问控制，而非 prompt 请求 | prompt 请求是软约束、会漏 |
| 调度机制 | 涌现式竞价，非中央导演 | 内部状态私有 → 只能靠自选 |
| 打断实现 | 块级重新竞价，非真流式 | 多 LLM 真流式打断延迟不可行 |
| 听众侧解释 | 必要，不可省略 | 没有它就没有「反应」 |
| urge 性质 | 动态状态（state + effect），非纯函数 | 「说完没」需要持续跟踪 |
| 场景收束 | 世界规则（diegetic），非导演拍板 | 结束有世界内理由，更真实 |
| 检测交给谁 | LLM 轻思考，非启发式/嵌入 | 启发式/嵌入对「挑衅我」这类判断不稳 |
| 发言权归谁（实现口径） | harness 数值 bid；LLM 自评 urge 以 `urge_gain` 加权计入（缺省 0.6，置 0 退回纯数值） | 纯 LLM 自报不稳/不可测；纯数值又浪费 LLM 对情境的判断；负冲动要有实际作用 |
| 被点名未答 | 待回应压力每轮 ×2 直到开口（封顶 64） | 只有邻接抬升时，被点名者常抢不过别人的沉默压力，"问了没人答" |
| 思考的上下文 | think 必须携带**自开场至今的全量可见转录** | 只看上一句会让思考退化成"接话"，看不出局势 |
| 场景何时结束 | 只由虚拟钟走到打烊或用户停止；**无块数收束** | 块数上限曾冒充"打烊"提前收场，误导且与真实时间脱节 |
| 文风 | 提示词内置去 AI 味硬规则（破折号仅限抢断/强说明两用；禁排比、AI 连接词、金句升华、模板化神态） | 生成文本 AI 腔重、神态描写千篇一律 |
