# Ensemble-AI-Studio 操作手册

面向使用者的完整说明。不需要编程经验，照着做即可。

- 仓库根目录下有 `app/`（程序与素材）与 `templates/`（模板）。
- Python 项目在 `app/` 里。发行名是 `ensemble`，import 包名是 `harness`。
- 文中所有命令都在 `app/` 目录下执行，除非另作说明。

---

## 1. 安装与启动

### 1.1 环境要求

| 项目 | 要求 |
| --- | --- |
| Python | 3.10 或更高 |
| 桌面应用 | 需要 PySide6 6.6 或更高 |
| 核心依赖 | langgraph、langgraph-checkpoint-sqlite、pydantic、httpx、PyYAML，安装时自动带上 |

### 1.2 创建虚拟环境并安装

Windows：

```bash
cd app
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[gui]"
```

macOS / Linux：

```bash
cd app
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[gui]"
```

说明：

- `-e` 是「可编辑安装」，装完之后 `harness` 包可以被 `python -m harness.…` 直接找到。改了源码不必重装。
- `[gui]` 是可选依赖组，只有它才装 PySide6。不装 PySide6 也能跑命令行，只是不能开桌面应用。
- 只跑命令行、不要界面时，用 `pip install -e .` 即可。

### 1.3 启动桌面应用

```bash
python -m harness.gui.app
```

首次启动会读到内置演示素材的缺省值：场景 `scenes/贝克街221B.json`，角色 `characters/福尔摩斯.json` 与 `characters/华生.json`。界面起手是**空状态页**，不会自动开演；场景由你自己在界面里挑。

常用旗标：

| 旗标 | 作用 |
| --- | --- |
| `--stub` | 强制离线 stub（占位台词，不联网） |
| `--scene <路径>` | 换一个场景 JSON |
| `--characters <路径> [路径…]` | 换一组角色卡 JSON |
| `--models <路径>` | 换模型档位 yaml，缺省 `config/models.yaml`；真实模型时自动改用同目录的 `models.live.yaml` |
| `--bid <路径>` | 换竞价参数 yaml，缺省 `config/bid.demo.yaml` |
| `--opening "开场白"` | 给本场一个开场设定 |
| `--autostart` | 跳过等待，直接按旗标/内置素材开演 |

例：

```bash
python -m harness.gui.app --stub
python -m harness.gui.app --scene scenes/贝克街221B.json --opening "深夜，雨刚停。"
```

### 1.4 命令行离线演示

```bash
cd app
python -m harness.runner --demo --stub
```

- 这个命令不联网、不起界面。两名角色在终端里一句一句实时打印，你按回车走下一句，输入 `q` 提前结束。
- 缺省素材同样是 `scenes/贝克街221B.json` + 福尔摩斯/华生。这些缺省路径是**相对于当前目录**的，所以必须在 `app/` 下运行。
- 常用附加旗标：`--prompt "开场指令"`（省掉交互式输入）、`--pace auto`（每句自动续演，不按回车）、`--max-steps N`（兜底步数护栏，缺省 60）、`--export 转录.md`（把转录导出成文件）。

### 1.5 `--live` 与 API 配置的关系

不写 `--stub` 且能拿到 API Key 时，程序才用真实模型；否则一律回退离线 stub。Key 的来源优先级是**从高到低**：

1. 命令行显式 `--stub`（最优先，谁也不能顶掉它）；
2. 桌面应用「设置 → 模型 api 配置…」里填的 API Key；
3. 环境变量 `DEEPSEEK_API_KEY`；
4. 以上都没有 → 离线 stub。

也就是说，**在设置里填过 Key 就不必再配环境变量**。服务地址与模型名称没有对应的环境变量，一律以设置为准（服务地址留空时用内置默认端点）。

两个命令行入口的缺 Key 行为不同，这是有意设计的：

| 命令 | 缺 Key 时 |
| --- | --- |
| `python -m harness.runner --demo` | 打印一句提示，自动回退 stub，绝不崩 |
| `python -m harness.runner --live` | 直接报错退出：`--live 需要 DEEPSEEK_API_KEY 环境变量` |
| `python -m harness.gui.app` | 自动回退 stub，左栏「真实模型」开关置灰 |

命令行示例：

```bash
# 用真实模型跑一遍离线批量（需 DEEPSEEK_API_KEY）
python -m harness.runner --live --steps 8 --export runs/转录.md

# 交互式演示，用真实模型（缺 Key 会自动退回 stub）
python -m harness.runner --demo
```

## 2. 界面导览

主窗口是三栏布局，中间用分栏线隔开，可拖动。

### 2.1 左栏（整栏可上下滚动）

自上而下五张卡：

| 卡片 | 内容 |
| --- | --- |
| 场景 | 场景名、日期（没设日期时整行不显示）、开始（虚拟钟起点）、当前（虚拟钟当前时刻，逐秒走）、边界（只有「时间」硬边界才给 HH:MM，其余一律「—」）、在场人数 |
| 运行指标 | 用时、消息、块数、思考 think、台词 speak。think/speak 两行显示「调用次数 · token 输入+输出」，超过十万走 k 单位 |
| 冲动 bid（实时） | 在场每名角色一行的实时条，谁此刻最可能拿话筒一眼可见 |
| 运行控制 | 暂停/继续、停止、真实模型开关、流速（0.25×–60×，默认 1×）、语速（0.5s–3.0s/句，默认 0.8）、开新场、场景库… |
| 场景推进 | 自动推进开关、推进一下、推进活跃度（少/中/多/极多）、状态行（自动开关态 · 距上次推进几块 · 上次理由 · 判据分） |

### 2.2 中栏

顶部一行：场景名页眉、后端药丸（真实模型 / 离线 stub）、状态 chip、「保存场景」、「配置场景」、「日志」开关。

其下是会话区，上下两块：

- 上半是**日志窗格**，默认收起。点「日志」展开，里面是各角色的 think 思考（仅人类可见）、场景诊断、场景变更记录。
- 下半是**对白区**。角色台词、场景叙述、你的插话都在这里按时间顺序排列。场景叙述行末尾带「撤销 / 改写」两个行内链接。

最底下是输入框和「发送」按钮。

未打开场景时，整个会话区收起，中栏显示**空状态页**（见 2.4）。

### 2.3 右栏

每名在场角色一张卡，卡上有该角色的设定摘要、性格权重、情绪衰减、语料，底部是「查看详情」按钮（只读弹窗，展示设定/能力/关系/性格权重/情绪衰减/语料）。

运行起来后，每张卡还会多出一块**实时分量**，随每一块刷新：冲动 bid、沉默轮数、相关度、唤醒、邻接、目标压力、场景压力、自报 urge、待回应压力、被点名/回应对象。被禁言的角色卡上会显示「禁言中」或「禁言中（剩 N 回合）」。

### 2.4 空状态页

软件启动后见到的第一屏。一句话说明加三个按钮：

| 按钮 | 作用 |
| --- | --- |
| 打开场景 | 从场景库里挑一个场景打开 |
| 新建场景 | 打开空白场景编辑器，保存后切到该场 |
| 新建角色 | 打开角色编辑器，存进角色库目录 |

### 2.5 顶栏三个菜单

**设置**

| 菜单项 | 说明 |
| --- | --- |
| 模型 api 配置… | 服务地址 / API Key / 模型名称，含「拉取模型」 |
| 配色 | 默认 / 深色 / 白色 / 深蓝，四选一 |
| 语言 | 简体中文 / 繁體中文 / English / Français / Deutsch / 日本語 / 한국어，七选一 |
| 自动保存周期 | 每 5 轮 / 每 20 轮 / 每 50 轮 / 每 100 轮 |

**场景**

| 菜单项 | 说明 |
| --- | --- |
| 打开场景 | 子菜单列出场景库里的场景，选中即打开 |
| 配置场景… | 编辑**当前场景**的全部信息，保存后当场生效 |
| 保存场景 | 把当前场景（配置 + 对话历史 + 虚拟钟 + 各角色进场时间）落盘 |
| 重置场景运行上下文… | 清空本场对话与思考上下文，保留配置与在场角色 |
| 管理场景库… | 打开场景库弹窗：打开 / 编辑 / 复制 / 删除 / 新建 / 从模板导入 |
| 新建场景 | 打开空白场景编辑器 |
| 导入场景… | 选一个按模板填好的 .md，解析成场景卡入库 |

**角色**

| 菜单项 | 说明 |
| --- | --- |
| 添加角色 | 动态子菜单，列出角色库里还不在场的人 |
| 移出角色 | 动态子菜单，列出本场在场的人 |
| 新建角色 | 打开角色编辑器，存进角色库目录 |
| 导入角色… | 选一个按模板填好的 .md，解析成角色卡入库 |
| 管理角色… | 本场演员表：添加 / 移出 / 编辑 / 删除（表格含姓名 / 在场 / 禁言状态三列） |
| 高级移入/移出… | 选人 + 移入或移出 + N 回合后执行 + 通知对象多选 |

没有打开场次时，「添加角色」「移出角色」等依赖场次的项会置灰，鼠标悬停会说明原因。

### 2.6 状态 chip 的含义

中栏顶部的状态 chip 用颜色和文字表示本场此刻的状态。

| chip 文案 | 颜色 | 含义 |
| --- | --- | --- |
| 就绪 | 灰 | 还没有开演 |
| 进行中 | 绿 | 引擎在跑，角色在自主对话 |
| 已暂停 | 琥珀 | 你点了暂停，虚拟钟冻结 |
| 等待中…可随时插话 | 灰 | 连续若干块没人说话，引擎在省 token 等你开口 |
| 已收束 | 蓝灰 | 场景正常结束（比如虚拟钟走到硬边界） |
| 已停止 | 红 | 你点了「停止」 |

另外两种临时状态：出错时 chip 刷红（含「开场失败」「保存场景失败」等字样）；因 token 守卫自动暂停时 chip 刷琥珀，文案是「已达 500 块，点继续以续演（防止 token 消耗）」。

## 3. 建立角色与场景

两条路：手工在应用里建，或者把素材交给大模型按模板填好再导入。两条路可以混用。

### 3.1 手工建

#### 3.1.1 角色编辑器

菜单「角色 → 新建角色」或「角色 → 管理角色… → 编辑角色」打开。字段如下。

| 字段 | 怎么填 |
| --- | --- |
| 姓名（必填） | 同时是文件名。空、含路径分隔符、以点开头等会当场报错 |
| 出处／作品 | 角色来自哪部作品；原创留空 |
| 语料 · 语言风格 | 措辞习惯、句子长短、爱用什么句式、忌讳什么说法 |
| 语料 · 思维方式 | 如何推理、先关注什么、如何做决定、情绪如何影响判断 |
| 语料 · 口头禅 | 一行一条 |
| 语料 · 台词样例 | 一行一条，用**原作原句**最好，3–5 条 |
| 性格 | 一行「键：值」，如 `冷静沉稳：先观察再开口` |
| 能力 | 一行一条 |
| 关系 | 一行「名字：关系」，如 `华生：室友与记录者` |
| 已知边界 | 一行一条。写清他**知道**什么、**不知道**什么 |
| 性格权重 w1–w7 | 七根 0–1 滑杆，含义见下表 |
| 情绪衰减 | 0–1 滑杆，越大消气越快 |

**语料四件套是决定「像不像」的关键**：语言风格、思维方式、口头禅、台词样例。语料只用来教模型「怎么说话、怎么想」，样例本身不会被照抄。

**权重 w1–w7 的含义与建议区间**：

| 字段 | 界面短名 | 含义 | 建议区间 |
| --- | --- | --- | --- |
| w1_relevance | 相关 w1 | 话题与他多相关时的影响 | 0.3–0.7 |
| w2_arousal | 唤醒 w2 | 情绪上头时的影响 | 冲动型 0.8–1.0；冷静型 0.2–0.4 |
| w3_adjacency | 邻接 w3 | 被点名、被挑衅时的影响 | 0.5–0.9 |
| w4_goal_pressure | 目标 w4 | 有非说不可的事时的影响 | 0.3–0.7 |
| w5_talkativeness | 话痨 w5 | 天生爱不爱开口 | 沉默寡言 0.2–0.4；话多 0.7–1.0 |
| w6_inhibition | 抑制 w6 | 克制与社会层级的刹车 | 克己 0.6–0.9；莽撞 0.0–0.2 |
| w7_scene_pressure | 场景 w7 | 公开场合、时间压力的影响 | 0.3–0.6 |

**情绪衰减**：0–1，越大消气越快。记仇型 0.1–0.3，不记仇型 0.6–0.9；缺省 0.4。

拿不准就用建议区间的中值，之后随时可以回来调。保存即写入 `app/characters/姓名.json`。

#### 3.1.2 场景编辑器

菜单「场景 → 新建场景」或「场景 → 配置场景…」打开。字段如下。

| 字段 | 怎么填 |
| --- | --- |
| 场景名 | 显示用，可随时改，不影响文件名 |
| 文件名 | 落盘用。新建时按场景名生成一次，之后改场景名不再跟着变。必须以 `.json` 结尾 |
| 设置日期 | 勾上才启用年/月/日三个数字框；不勾即不设日期 |
| 开始时间 | `HH:MM`，虚拟钟起点。缺省 `21:30` |
| 背景信息 | 世界观与设定：规则、势力、前情。所有角色共享的公共信息 |
| 场景描述 | 这个地点**现在**什么样：陈设、光线、气味。具体可感 |
| 可改变的 | 勾上后，场景可以在剧情推进时改写上面的描述（见第 7 节） |
| 剧情设定 | 你希望接下来往哪走。走向、悬念或目标 |
| 硬边界 · 类型 | 五选一：无 / 时间 / 物理 / 社会 / 目标 |
| 硬边界 · 边界值 | 类型为「时间」时填 `HH:MM`（如 `22:00`）；类型为「无」时停用 |
| 硬边界 · 边界描述 | 一句话说明这个边界的含义，如「就寝」「餐厅打烊」。会用于到点收束的提示语 |
| 出场角色 | 勾选 = 在场。列表上方有「出场作品筛选」下拉，可按角色的出处归类筛选 |
| Hooks | 触发器列表，下方有「新建 / 编辑 / 删除」三个按钮（见第 6 节） |

出场角色列表**最多显示 6 行**，超过 6 个自动出现滚动条，不会把弹窗越撑越长。列表里同时列出角色库里已有的卡和场景原有但库里没有卡的名字（不悄悄丢人）。

出场角色**可以一个都不勾**。空场是合法场次，照样能开场（见 5.4）。

硬边界类型选「无」时，边界值与描述两个框一并停用——不设边界，引擎就不会自动收束。

编辑器底部另有「重置场景」按钮，它清的是各角色的**入场记录**，与菜单里那个「重置场景运行上下文…」不是一回事（见 9.4）。

保存前的校验：场景名非空、文件名合法且以 `.json` 结尾、开始时间是 `HH:MM`、时间边界的值也是 `HH:MM`、每个勾上的角色都有角色卡、每条 hook 合法。任何一条不过就地红字报错，不关窗。

### 3.2 从素材导入

三步走。

**第一步：把模板和素材一起交给大模型**

复制 `templates/角色卡模板.md` 或 `templates/场景卡模板.md` 的**全文**，连同你的小说或剧本素材（原文片段即可，越长越准），一起发给任意大模型，并附一句话：

> 请严格按这份模板的填写说明，依据下面的小说素材填写。保留所有【】字段名与结构，不要输出 JSON，不要编造素材里没有的内容。

**第二步：检查填写结果**

- 字段名是否原样保留（`【姓名】` 这类，连同方括号与冒号）；
- 【台词样例】是否是**原句**（不是模型改写的）；
- 权重是否是 0–1 的小数；
- 场景卡的【出场角色】是否都是**已有角色卡**的姓名。

**第三步：导入库中**

命令行：

```bash
cd app

# 角色卡 → app/characters/
python -m harness.tools.import_cards ../templates/填好的角色卡.md

# 场景卡 → app/scenes/（角色卡/场景卡由文件内容自动识别，不必指定类型）
python -m harness.tools.import_cards ../templates/填好的场景卡.md

# 只看解析结果，不写盘
python -m harness.tools.import_cards 某文件.md --dry-run

# 指定场景文件名（缺省按场景名生成安全文件名）
python -m harness.tools.import_cards 某场景.md --name 我的场景.json

# 目标文件已存在时覆盖（缺省会拒绝并报错）
python -m harness.tools.import_cards 某文件.md --force

# 一次导多个文件
python -m harness.tools.import_cards a.md b.md --dry-run
```

另外两个可选旗标是 `--characters-dir` 与 `--scenes-dir`，用来指定落盘目录；不给就用 `app/characters/` 与 `app/scenes/`。

`--name` 只对**场景卡**有意义。文件名的目标位置按程序自身所在目录解析，所以在哪个目录下执行命令都会落进同一个库。

导入器逐个文件打中文报告：

```
√ 角色卡《福尔摩斯》（../templates/福尔摩斯.md）
  已写入：…/app/characters/福尔摩斯.json
  以下字段模板里没填，已用默认值：唤醒权重 w2、情绪衰减
  提示：……
```

试运行时不写盘，那一行变成「目标位置：（试运行，未写盘）」。

解析失败只说人话，格式是：

```
文件名 → 第 N 行附近 字段【X】：消息
```

照这一处改完再导入即可。一个文件失败不影响剩下的文件继续处理。命令的退出码是 0，当且仅当每个文件都成功（试运行也算成功）。

**在应用里导入**

菜单「场景 → 导入场景…」或「角色 → 导入角色…」，也可以从场景库弹窗底部的「从模板导入…」进。选一个填好的 `.md` 即可。导入结果会弹窗告诉你：导入了哪张卡、落在哪里、**哪些字段模板里没填而已用默认值**、以及解析提示。库里已有同名文件时会拒导——先改名或删掉旧文件。

导入成功后，新素材会出现在「场景」「角色」两个菜单的库里，可直接选用。

## 4. 一场戏怎么跑起来

### 4.1 打开场景

三条路都行：空状态页的「打开场景」、菜单「场景 → 打开场景」、菜单「场景 → 管理场景库…」。选中一个场景即打开。

打开时如果发现这个场景有上次留下的存档，会先问一句「检测到上次的存档，接着上次继续演吗？」（见第 9 节）。

切场前程序会先校验素材（场景文件读得出、点到的角色都有卡、时间格式合法）。校验不过只弹提示，当前场次原样保留，不会把正在进行的对话弄丢。

### 4.2 自动对话如何推进

开场后角色**自主开口**，不需要你逐句点。引擎一块一块地跑，每一块内部：

1. 在场且未被禁言的每名角色各得到一次 think（思考）；
2. 各自的数值 bid 竞价，谁的分最高谁拿到话筒 speak（说出台词）；
3. 场景自己的推进判据也在算（见 4.5）。

**事件门控**：只有在**有人说话**的时候引擎才继续往下想。一块跑完没有任何新消息，就进入静默容忍窗口；连续静默超过窗口，状态就转成「等待中…可随时插话」，此时引擎不再空转烧 token，等你开口。

### 4.3 你的插话

底部输入框输入内容，回车或点「发送」。

- 你的话**立即上屏**，不用等下一个模型往返；
- 角色在下一块就会接你的话；
- 暂停中发送会自动解除暂停；
- 场景已收束时发送会被拒绝，chip 提示「场景已收束，可点开新场」；引擎正在切换时提示「场景未就绪，稍候再试…」。

### 4.4 暂停 / 继续 / 停止 / 开新场

| 操作 | 位置 | 行为 |
| --- | --- | --- |
| 暂停 | 左栏「运行控制」 | 引擎停止推进，虚拟钟冻结（流速不变，只是钟不走）。按钮变「继续」 |
| 继续 | 同上 | 恢复推进；因 token 守卫暂停时点它会清零计数器重新计数 |
| 停止 | 同上 | 立即收束本场，不可撤销。停止后暂停/继续失效，但「开新场」仍可用 |
| 开新场 | 同上 | 按当前配置重新开场。自然收束或停止之后依然可用 |

### 4.5 推进活跃度

左栏「场景推进」卡里的下拉，四档：

| 档位 | 数值 | 含义 |
| --- | --- | --- |
| 少 | 0.2 | 尽量少介入，把戏留给角色自己演 |
| 中 | 0.5 | 适度介入，卡住或需要外界变化时再推一步（缺省） |
| 多 | 0.8 | 多介入一些，主动把局势往前带 |
| 极多 | 1.0 | 尽量主动介入，频繁给出新的外界变化 |

这个旋钮同时做两件事：

1. **缩放判据**。档位越高，触发线越低、冷却越短。规则两条，写成公式是：触发线乘 `1.3 − 0.6 × 档位`，冷却乘 `1.6 − 1.2 × 档位`（冷却取整）。「中」（0.5）正好是恒等点，与引入这个旋钮之前的行为完全一致；「少」（0.2）约为触发线 ×1.18、冷却 ×1.33；「多」（0.8）约为触发线 ×0.82、冷却 ×0.64；到 1.0 时是触发线 ×0.7、冷却 ×0.4。
2. **写进场景提示词**。引擎只决定「什么时候叫场景」，叫来之后到底写不写、写多少，由场景自己按当前档位把握。

同一张卡里还有：

- **自动推进**开关：关掉后引擎不再自动叫场景，钩子也不再自动判定。「推进一下」手动推进照常可用，且手动推进时仍会带上钩子清单。
- **推进一下**按钮：立刻让场景推进一步，无视冷却。
- **状态行**：显示「自动推进中 / 自动已关（可手动推进） · 距上次推进 N 块」「上次理由：…」「（判据 1.23）」。

### 4.6 流速（虚拟钟）与语速

- **流速**：左栏下拉，0.25× 到 60×，默认 1×。它控制场景内虚拟钟走多快。1× 时 21:30 到 22:00 约对应 30 真实分钟。调速时会先折现当前时刻再换挡，不丢时间。
- **语速**：左栏滑杆，0.5 秒到 3.0 秒一句，默认 0.8。它控制每块之间的节拍，也就是角色「说话」的快慢。

两者互不相干：流速管虚拟钟，语速管块与块之间的间隔。

### 4.7 到达硬边界自动收束

场景的硬边界类型是**时间**时，虚拟钟走到该时刻，场景自动收束，并落一行收束语（用你写的边界描述；没写描述就用一句中性兜底）。

硬边界类型是「无 / 物理 / 社会 / 目标」时，**不会**自动收束，靠你点「停止」或场景推进自然结束。

## 5. 角色进出场

### 5.1 添加与移出

- 菜单「角色 → 添加角色」：子菜单列出角色库里还不在场的人，点一个即让他进场。已在场的人不出现在这个子菜单里。
- 菜单「角色 → 移出角色」：子菜单列出本场在场的人，点一个即让他离场。**历史与角色卡都保留**，随时可以再加回来。
- 菜单「角色 → 管理角色…」：一张表格列出本场全部演员表（姓名 / 在场 / 禁言状态），下方有「添加角色 / 移出角色 / 编辑角色 / 删除角色」四个按钮。「编辑角色」改的是角色卡本身，不动本场演员表；「删除角色」会删掉磁盘上的卡文件（要确认），但本场在场状态不受影响。

进场时引擎会落一条可见的「（X 走进了场景。）」；离场同理。已经在场的人再点一次「添加」是空操作，不会重复播报。

### 5.2 禁言与解禁

禁言与解禁只能通过 **hook 的角色事件**来做（见 6.2），界面里没有直接的禁言按钮。

- 被禁言的人连 think 都不发（不烧 token），也拿不到话筒，话自然落到别人手上；
- 解禁后立刻回到名单；
- 移出本场会清掉他的禁言状态，再进场是干净状态；
- 「管理角色…」弹窗的「禁言状态」列会显示「禁言中」（长期）或「禁言中（剩 N 回合）」（限时）。左栏冲动条与右栏角色卡上也有同样的徽标。

### 5.3 高级移入移出

菜单「角色 → 高级移入/移出…」打开。三个设置：

| 设置 | 说明 |
| --- | --- |
| 角色 + 动作 | 选一个人，勾「移入（加入本场）」或「移出（离开本场）」 |
| 多少回合后执行 | 0 = 下一个块末立即执行；N = 再走 N 块之后执行。上限 99 |
| 通知 | 勾上后可多选通知对象：在场角色 + 他自己 + 「场景」。勾上后另落一条**只给这些人看**的通知行 |

通知内容留空时用默认一句「（X 来了。）」或「（X 走了。）」。通知对象里的「场景」表示这条通知不进任何角色的视野。

延时执行的动作全部在引擎侧排队，左栏「场景推进」的状态与日志里能看到「还需 N 轮」的进度。

### 5.4 进场者看不到进场前的对话

这是硬语义：**一个人进场之前的对话，他一句都看不到**。引擎按转录轮次记下他的进场基线，视图里进场基线之前的内容对他来说不存在。

但他能看到**公共信息**：场景名、场景背景、场景描述、剧情设定。所以「这是个什么世界、现在什么走向」对新来者仍然清楚。（当前时刻只有场景/叙述者那一档看得到，角色不直接读钟。）

### 5.5 空场可运行

场景可以一个角色都没有，照样能开场。空场时「添加角色」仍然可用——角色库目录会依次回落到场景目录的兄弟目录 `characters/`，再回落到内置的 `app/characters/`。

## 6. hooks 完全指南

一条 hook = **条件** + **事件**。场景每一轮都会看一遍这些条件，条件成立就执行对应事件。

hook 在场景编辑器里管理：「新建 / 编辑 / 删除」三个按钮，列表里每行显示 `〔备注〕若『条件』→ 效果（显式/隐式）`，被停用的会加一句「（已停用）」。

### 6.1 条件

用自然语言写就行，由场景自己判定。例：

- `有人提起一桩未结的案子`
- `两人已经开始互相指责`
- `虚拟钟走到 22:30`

**时间类条件由引擎确定性校验**。只要条件里**同时**出现一处钟点（`21:30`、`9:05`、`21点30分`、`22点`）与一个钟表词（虚拟钟 / 时间 / 钟点 / 时刻 / 到点 / 走到 / 到了 / 已经到 / 之后 / 晚于 / 打烊 / 开门），引擎就会在执行前核对一次当前虚拟钟：

- 钟点还没到 → 即使场景模型报「条件成立」，事件也不执行；
- 钟点已到 → 正常执行；
- 此刻钟点未知 → 不推翻场景的判断，只记一条诊断。

只有钟点（如「有人提起 21:30 那件事」）或只有钟表词（如「到点了」）都不算时间闸门，交回场景自己判。跨午夜按本场开场时刻换算：19:00 开场时写「虚拟钟走到 00:30」，指的是**次日** 00:30。

### 6.2 三类事件

| 事件类型 | 载荷 | 说明 |
| --- | --- | --- |
| 上下文事件 | 一段文本 | 把这句话写进对话（所有人可见的一条叙述） |
| 角色事件 | 角色名 + 动作（+ 静默轮数） | 让某角色加入 / 离场 / 静默 N 轮 / 长期静默 / 解除静默 |
| 场景事件 | 一行「键：值」 | 改写场景自身 |

角色事件的五个动作：`加入`、`离场`、`静默 N 轮`（N 必须大于 0）、`长期静默`、`解除静默`。角色名可以手填列表里没有的名字（但库里得真有这张卡，否则执行时会报「角色库里没有找到《X》的角色卡」）。

场景事件**只能改这五个字段**：`name`（场景名）、`description`（场景描述）、`background`（场景背景）、`plot_direction`（剧情走向）、`date`（日期）。

写的时候可以直接用这五个真键，也可以写界面上给的中文名（`场景名 / 场景描述 / 场景背景 / 剧情走向 / 日期`），甚至写口语简称（`描述 / 背景 / 剧情 / 剧情设定 / 场景 / 名字`），导入与保存时会自动换成真键。

**文件名与路径永远是磁盘身份，任何 hook 都改不到它。**

### 6.3 显式与隐式

编辑 hook 时的「显式」勾选框：

- **勾上（显式）**：这件事会出现在对话框里，读者看得见。
- **不勾（隐式）**：只在后台生效，读者看不到。隐式事件不落任何对话行（连角色进出的播报行、通知行也不落），只在日志面板里留一条记录——那是它唯一的可见痕迹。

### 6.4 写多个角色动作

一条 hook 的「事件内容」里可以写多个角色动作，用**换行或分号**分隔：

```
华生：离场；福尔摩斯：离场
```

按模板导入时，每个动作会各自展开成一条独立的 hook（上例会变成两条）。这样一条「某条件成立则两人一起走」的设定，写起来只写一遍。

### 6.5 常见写法示例（用贝克街演示）

内置场景 `app/scenes/贝克街221B.json` 里就有两条：

| # | 条件 | 事件 | 显隐 |
| --- | --- | --- | --- |
| h1 | 有人提起一桩未结的案子 | 上下文：`福尔摩斯把烟斗从唇边移开，眼里那点倦意一扫而空——他坐直了。` | 显式 |
| h2 | 虚拟钟走到 22:30 | 角色：华生 离场 | 显式 |

在这个场景上再加几条，可以这么写：

| 条件 | 事件类型 | 事件内容 | 显隐 |
| --- | --- | --- | --- |
| 两人开始互相指责 | 场景 | `description：两张扶手椅之间多了一只打翻的茶杯，地毯上洇开一片。` | 显式 |
| 华生已经离开 | 上下文 | `壁炉里的火小了下去，只剩一层暗红。` | 显式 |
| 有人提起莫里亚蒂 | 角色 | `福尔摩斯：静默 2 轮` | 隐式 |

最后一条的意思是：这个话题让他沉默两个回合，但读者看不到「他被禁言了」这件事。

### 6.6 排错：诊断在哪里看

| 想知道什么 | 去哪里看 |
| --- | --- |
| 场景为什么没执行某条 hook、某条指令被拒了 | 中栏「日志」按钮展开日志面板，找「场景诊断：…」；同时状态 chip 也会提示一次 |
| 场景推进为什么没触发、上次为什么触发 | 左栏「场景推进」卡的状态行：「上次理由：角色在复读；久未推进」加「（判据 1.23）」 |
| 隐式事件到底发生了什么 | 日志面板里的「（隐式事件：…）」 |
| 场景改了哪些字段 | 日志面板里的浅红「场景变更 · …」行 |
| 某条 hook 是否启用 | 场景编辑器的 hook 列表：「（已停用）」后缀 |

两条容易踩的规则：

- **hook 的 id**（引擎内部用，编辑器自动分配）只能用字母、数字、下划线、点、连字符，且同一场景里不能重名。不合法或重名的 id 引擎永远认不出来，编辑器会在保存时拦住。界面上没有 id 输入框，通常不用操心。
- **条件不能为空**。上下文事件必须填文本，角色事件必须填角色名，场景事件必须至少改一个字段——这几条编辑器都会当场拦住。

## 7. 场景会自己改自己

### 7.1 打开「可改变的」

在场景编辑器里勾上「可改变的（允许场景改写上面的描述）」，这个场景就获得了改写自己的能力。

勾上之后，场景若判断该变天了，会调用几个内置工具：

| 工具 | 作用 |
| --- | --- |
| `set_description` | 替换场景描述 |
| `append_description` | 在场景描述末尾追加一段 |
| `set_background` | 设置场景背景 |
| `set_name` | 设置场景名字（只改名字） |

所以模板里那句例子是成立的：`餐厅里有一些桌椅` 可以被改写成 `餐厅里有一些破碎的桌椅，到处都是战斗后的痕迹`。

### 7.2 改完会额外思考一次

场景调用工具改完场景后，引擎会把**改后的新描述与新背景再喂回场景**，让它多想一次——这样这一轮的叙述能考虑进「我刚改了什么」。这个额外思考**只多一次**，第二轮即使再产生工具指令也只照改、不再触发第三次思考，防止模型自我循环。

**没有勾「可改变的」时**，场景发出的工具指令被忽略，并记一条诊断：场景未标为「可改变」→ 忽略了 N 条场景工具指令。

### 7.3 改了哪些字段在哪里看

所有场景自身的改动（不管是工具改的、hook 改的还是你手动配置的）都会在**日志面板里以浅红高亮**落一行：

```
· 场景变更 · 描述 → 餐厅里有一些破碎的桌椅，到处都是战斗后的痕迹
```

值很长时按新值显示；值为空时显示「（空）」。隐式变更同样会落这一行——它不进对话，这条浅红记录就是它唯一的可见痕迹。

另外，场景名被改掉之后，窗口标题和中栏页眉会同步更新。**文件名不会变**——那是磁盘身份。

## 8. 撤回与改写

场景叙述行末尾有「撤销 / 改写」两个行内链接。角色台词行没有这两个链接，只有场景推进可以撤回。

### 8.1 撤销 = 整段回溯

点「撤销」会弹出确认框：

> 撤销这条场景推进会把**它之后的所有内容**一并丢弃，此后不再出现在任何上下文中。确定撤销吗？

确认后：

- 这条推进**以及它之后的全部内容**一起作废（不只是这一条）；
- 角色的**私有记忆按轮次截断**——他们此后不会记得这段发生过；
- **think 日志也按轮次截断**；
- 界面立即截断显示，不等引擎往返。

**不可逆。** 所以确认框默认选「否」，误点不会把一场对话清空。

### 8.2 改写 = 回溯后重写

点「改写」会先弹一个多行输入框，预填这条叙述的当前文本。改完点确定，再弹一次确认：

> 改写会**回溯到这条推进**：它之后的所有内容会被一并丢弃，此后不再出现在任何上下文中，随后写入你改写后的叙述。确定改写吗？

也就是说，改写等于「撤销 + 写入新内容」，代价与撤销一样。输入为空会被拒绝（提示「改写内容为空，已忽略」），原内容一字不动。

## 9. 保存、续演、重置、自动保存

### 9.1 旁挂存档文件是什么

保存一次写**两份文件**：

| 文件 | 里面是什么 |
| --- | --- |
| `<场景>.json.runtime.json` | 旁挂存档（sidecar）。对话转录、虚拟钟当前秒数、已跑块数、在场与禁言状态 |
| `<场景>.json` | 场景文件本身。**只把当前的出场角色写回它的 characters 字段**，其余配置（名/日期/背景/描述/剧情/hooks/边界/开始时间）一字不动 |

也就是说，运行期的角色增删会被写回场景文件——这样进程意外退出时，加进来或移出去的人不会丢。存档与场景文件同目录、同名前缀：

```
贝克街221B.json  →  贝克街221B.json.runtime.json
```

用旁挂存档而不是把运行状态全塞进场景文件，好处有三个：

- 场景文件的格式一个字段都没多，别的工具照样读；
- 写坏也坏不到场景本体——落盘走「同目录临时文件 + 原子替换」，断电时要么看到旧的完整存档，要么看到新的完整存档，绝不会看到半截 JSON；
- 存档是可丢的**缓存**而非资产：文件缺失、空文件、JSON 坏了，一律当作「没有存档」，程序照常按场景配置开场。

`app/.gitignore` 里已经忽略了 `*.runtime.json`，存档不会进版本库。

### 9.2 保存按钮与自动保存周期

- **手动保存**：中栏「保存场景」按钮，或菜单「场景 → 保存场景」。写的就是上面那两份文件。成功后状态 chip 报「已保存：<场景文件名>」。当前场景若未落盘（比如你是从内存里新建的），会明确提示「当前场景未落盘，无法保存」，绝不假装保存。收束之后再点保存照样有效。
- **自动保存**：菜单「设置 → 自动保存周期」选 5 / 20 / 50 / 100 轮，默认 20。每成功推进一个块计一次，累计到周期就在块末静默存一次（同样是那两份文件）。判定按**累计差**而非块号取模，所以周期中途从 20 改成 50 也不会漏一次或误触发。写盘失败只记诊断，不会打断正在跑的对话。

### 9.3 下次打开

打开一个有存档的场景时，会先问：

> 检测到上次的存档，接着上次继续演吗？

默认「是」。选「是」就恢复上次的对话、虚拟钟与各角色进场时间，接着演。选「否」会**删掉这份存档**，从头开始演——这是你明确的选择，不是静默丢弃。

### 9.4 两个「重置」的区别

这是最容易混淆的一对，务必分清：

| 入口 | 清什么 | 保留什么 | 动不动磁盘 |
| --- | --- | --- | --- |
| 菜单「场景 → 重置场景运行上下文…」 | 本场的**对话与思考上下文**（对话、think 日志、角色私有记忆） | 场景配置、在场角色名单 | 不写盘，也不删存档 |
| 场景编辑器底部的「重置场景」 | 各角色的**入场记录**（谁何时进来的） | 场景配置、在场角色名单 | 把当前表单内容**写回场景文件** |

编辑器里那个「重置场景」写盘时，用的是编辑器**当下**的表单内容，所以未保存的改动会一并落盘；表单校验不过时它会先报错、不写盘。

一句话记法：前者清**对话**，后者清**入场记录**。

「重置场景运行上下文…」做的是：把本场已有的每条消息都标记作废（等于逐条撤销的效果）、清空 think 日志、清空每名在场角色的私有记忆、把数值动态按当前在场名单重新播种、叙述判据归零。它**不碰磁盘上的场景文件，也不删除存档文件**——要不要丢弃存档，由你自己用「保存场景」或场景库管理来决定。确认框默认「否」，误点不会有任何后果。

## 10. 设置

### 10.1 模型 API

菜单「设置 → 模型 api 配置…」：

| 字段 | 说明 |
| --- | --- |
| 服务地址 | 如 `https://api.deepseek.com`。留空用内置默认端点 |
| API Key | 密码态显示，旁边有「显示」开关可切明文 |
| 模型名称 | 可手填，也可用下面的「拉取模型」选 |
| 拉取模型 | 请求 `{服务地址}/models`，把返回的模型 id 列进下拉；选中一个即填进「模型名称」 |

拉取在后台线程里跑，失败只在弹窗里红字提示，不会卡住界面。

保存后这份配置写入用户数据目录的 `settings.json`（见 10.5）。填过 API Key 之后，左栏的「真实模型」开关就会解锁（没 Key 时它是灰的）。

**优先级**（高 → 低）：显式 `--stub` > 设置里的 API Key > 环境变量 `DEEPSEEK_API_KEY` > 离线 stub。服务地址与模型名称没有环境变量版本，一律以设置为准。填了模型名称时，它会覆盖 think / speak / narrate 三档的模型名。

### 10.2 配色

菜单「设置 → 配色」，四选一：默认 / 深色 / 白色 / 深蓝。切换即时生效，包括对白区、左右栏与日志的配色。

一个已知限制：**已经打开的弹窗不会跟着换色**——Qt 不做全局重刷。之后新开的弹窗才是新配色。

### 10.3 语言

菜单「设置 → 语言」，七种：简体中文、繁體中文、English、Français、Deutsch、日本語、한국어。

**覆盖范围**：主界面与库弹窗里的静态文案——菜单、按钮、标签、悬停提示、输入框占位文本、状态 chip。切换即时生效，不必重启。

**覆盖不到的地方**：带数字或现场原因的动态串会原样显示，比如「已达 500 块，点继续以续演（防止 token 消耗）」「开场失败：…」。这是有意为之：宁可留着中文的现场信息，也不要为了翻译把它吞掉。

**其余回退中文的现状**：简体中文是主文案目录，要求完整；其余六种允许残缺。某个键在小语种里没翻译时，会自动回退显示简体中文。所以切到小语种后看到部分中文是预期行为，不是故障。

另外，LLM 的作答语言也会跟着这个设置走（引擎会给模型一行指令，指定用该语言回答）。但角色语料与场景文本仍是你写什么就是什么，不受影响。

### 10.4 自动保存周期

菜单「设置 → 自动保存周期」，5 / 20 / 50 / 100 轮，默认 20。含义见 9.2。

### 10.5 设置存在哪里

设置**存在用户数据目录**，不在仓库里，也不随项目走。

| 系统 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\Ensemble-AI-Studio\settings.json` |
| macOS / Linux | `$XDG_CONFIG_HOME/Ensemble-AI-Studio/settings.json`（未设则 `~/.config/Ensemble-AI-Studio/settings.json`） |

想知道你这台机器上的真实路径，跑这一句：

```bash
python -c "from harness.gui.settings import default_settings_path; print(default_settings_path())"
```

（这条命令只依赖标准库，不需要装 PySide6。）

设置文件是纯文本 JSON，可以直接用文本编辑器改。改坏了也不会把软件挡在门外：文件缺失、语法错误、字段非法，一律回落到该项的默认值——非法的那一个字段回默认，其余字段照旧保留。

## 11. 常见问题

### 11.1 开场就失败

几种最常见的原因，程序都会在切场**之前**拦下并说清是谁、哪里不对：

| 提示 | 原因 | 怎么办 |
| --- | --- | --- |
| 「这些参与者没有对应的角色卡：…」 | 场景声明了某个人，但角色库里没有他的卡 | 在角色库里建一张同名卡，或打开场景编辑器取消勾选他 |
| 「角色卡姓名重复：…」 | 两张卡用了同一个姓名 | 改掉其中一张的姓名 |
| 「场景开始时间不是合法时间：…（需 HH:MM）」 | 开始时间格式不对 | 改成 `21:30` 这样的格式 |
| 「时间边界的值不是合法时间：…（需 HH:MM）」 | 时间边界的值格式不对 | 同上，或把边界类型改成「无」 |

素材打不开时只弹提示，**当前场次原样保留**，正在进行的对话不会丢。

注意：**空阵容不是错误**。场景一个角色都没有也能开。

### 11.2 打开场景后没人说话

依次排查：

1. **没人在场**——空场。用「角色 → 添加角色」加人。
2. **全员被禁言**——看右栏角色卡上的「禁言中」徽标，或「管理角色…」弹窗的禁言状态列。禁言只能靠 hook 的「解除静默」事件解除。
3. **判据未到**——「自动推进」开关被关掉了；或者活跃度偏低而局势又没到触发条件（复读、久未推进、久无人接话、临近打烊）。办法：把活跃度调高，或点一次「推进一下」。
4. 状态 chip 停在「等待中…可随时插话」，说明引擎在等你——直接往输入框里说一句即可。

### 11.3 场景推进太频繁或者太少

- **太频繁**：把「推进活跃度」往下调（多 → 中 → 少）。另外检查 hook 条件是不是写得过宽（比如写成了每轮都成立），那种情况下场景每块都会判它成立。
- **太少**：把活跃度往上调（中 → 多 → 极多）。
- **完全不想要自动推进**：关掉左栏「自动推进」开关。此时「推进一下」仍然可用。

一条容易误解的规则：**被叫去判钩子不等于要写一条叙述**。有 hook 的场景，引擎每块都会咨询一次场景（让它判钩子），但只有这一轮真给出正文时才会在对白区落一行。所以「推进」和「叙述」是两件事。

### 11.4 导入报错怎么读

格式固定为：

```
文件名 → 第 N 行附近 字段【X】：消息
```

- `第 N 行附近` 是个大概位置，对着模板看那一带的字段；
- `字段【X】` 是模板里那个字段名（连同方括号），照着它找；
- 冒号后面是原因。

行号或字段名识别不出来时，那一段会省略，只留消息。**只改那一处，再导入一次即可**；一个文件失败不影响其余文件。

### 11.5 中文乱码

- 在终端里看到乱码，先设终端编码。Windows 命令行执行 `chcp 65001`；跨平台可以设环境变量 `PYTHONIOENCODING=utf-8`。
- 仓库里附带的两个启动脚本（`app/启动应用.bat`、`app/start-demo.bat`）都已经设好 `chcp 65001` 与 `PYTHONIOENCODING=utf-8`，双击运行不会乱码。
- 导出转录、保存场景、写设置文件一律用 UTF-8，不随系统区域设置变化。

### 11.6 token 消耗与 500 块自动暂停

引擎每成功推进一块计一次数。**累计到 500 块**时会自动暂停，状态 chip 显示：

> 已达 500 块，点继续以续演（防止 token 消耗）

这不是收束。虚拟钟冻结、对话保留，点「继续」即可接着演，计数清零、重新开始计。守卫暂停期间往输入框里插一句话同样会解除暂停并清零（插话被视作一次手动续演）；没有处在暂停状态时插话不影响这个计数。

这个间隔是固定的，界面上没有对应旋钮。想少烧 token，可以关掉「自动推进」、把活跃度调低，或者干脆盯着状态随时暂停。另外，平时挂机烧 token 还有第二道闸门——「事件门控」：连续若干块没人说话，引擎会自动转入「等待中…可随时插话」，那时它不再空转。

随时可以在左栏「运行指标」里看 `思考 think` 与 `台词 speak` 两行的调用次数与累计 token。

## 12. 术语表

| 术语 | 含义 |
| --- | --- |
| **bid（数值冲动）** | 引擎每一轮给在场每名角色算出的综合分，衡量「此刻他多想要话筒」。左栏「冲动 bid（实时）」条与右栏角色卡上的「实时分量 · 冲动 bid」同源，随每块实时移动 |
| **urge（自报冲动）** | 角色自己在 think 里给出的自评，范围 −1 到 2，可以为负（表示不想说）。它按权重计入数值 bid，但不是唯一决定项 |
| **think / speak** | 两块模型调用。think 产出锁死格式的思考结果（唤醒度、目标推进、urge 等）；speak 产出这一轮真正说出口的台词 |
| **narrate** | 场景/叙述者这一档模型。只在需要推进时开口，写一到两行「实际发生了什么」。配置缺这一档时自动退回 speak 档 |
| **hook（触发器）** | 一条「条件 + 事件」。场景每轮判断条件是否成立，成立就执行对应事件 |
| **进场基线** | 记录一个人是「从哪一轮开始在场」的分界线。进场基线之前的对话对他不可见，这是硬语义 |
| **待回应压力** | 别人对他说了话、而他还没回应时累积的压力，计入 bid。压力越高越容易开口 |
| **活跃度** | 场景自动推进的频率档位：少 / 中 / 多 / 极多，对应 0.2 / 0.5 / 0.8 / 1.0。它同时缩放触发线与冷却，并被写进场景提示词 |
| **虚拟钟** | 场景内的时钟。从「开始时间」起步，按全局流速走；有「时间」硬边界时，走到边界即自动收束 |
| **隐式事件** | `visible` 为假的 hook 事件。不落任何对话行，只在后台改状态，日志面板里的那条记录是它唯一的可见痕迹 |
