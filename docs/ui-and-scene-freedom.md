# 界面与场景自由度 — 优化需求与方案

> **摘要**：本文记录第三、四批优化需求（需求条目原文）及其落地方案：**场景持有阵容**与按需装卡、空场可运行、界面结构（去启动小窗 / 只保留场景库 / 配置场景 / 导入）、场景变更进日志、视觉语言（科技感、无 AI 味），以及第四批的**撤回回溯整段下文**与**自动推进频率可调**。与《场景编排与桌面外壳_设计文档》冲突处以本文为准。
>
> **对应代码**：引擎侧 `app/src/harness/engine.py`（阵容权威、`add_character`、`retract` / `edit_narration`、`set_narrate_activity`）、`scenarist.py`（场景开口判据与活跃度缩放）、`hooks.py`、`scenestore.py`（运行态 sidecar）、`template_import.py`（导入角色/场景）；界面侧 `app/src/harness/gui/`（`main_window.py`、`library.py`、`settings.py`、`theme.py`、`worker.py`）。
>
> **读者**：要改界面或场景自由度行为的人先读本文，再对照 `docs/design.md`（调度语义）与 `docs/technical-scheme.md`（模块划分）。本文所记 T1~T5 分期与第四批需求均已落地，正文保留需求原文与当时的根因分析。

## 一、需求原文（逐条记录）

1. **导入功能进应用**：顶栏「角色」菜单加「导入角色」，「场景」菜单加「导入场景」。
2. **取消启动小窗**：打开软件后**直接进入主界面**（一个**空聊天页**），用户在顶栏「场景」里打开场景；空项目页面**中央**放三个按钮：「打开场景」「新建场景」「新建角色」。
3. **修复场景与角色的关系**（用户诊断的三个设计问题）：
   - （1）**场景不储存人物**，每次启动都要手动重选 → 不符合设计预期。**场景应在任何时候都存住它其中的人物状态**，包括点击保存之后。
   - （2）**场景没有人也要能启动**——只是"没有人在活动"而已。
   - （3）**构造期没选中的人物，后续也加不进来** → 不符合预期。要求**人物与场景完全自由**：场景里计算发言的调度器**随人物表更新而更新**，前端一切显示**随角色增删而更新**，且**所有状态都会被保存**。
   - 配套决定：**摒弃原来的「角色/场景库」界面，只保留「场景库」**；初始人物只在**编辑场景 / 新建场景**里选；后续增删角色**随时可做**。
4. **新增「配置场景」按钮**（放在「保存场景」旁边）：点击进入编辑当前场景的弹窗，可改**场景的全部信息**。
5. **场景 agent 对场景信息的更改必须显示在日志中**，并用**浅红色高亮**。
6. **整体视觉优化**：要有**科技感、简约、高级**，**不能有 AI 味**（例如滥用 emoji）。记录并要求落地。

## 二、问题根因（第 3 条）

| 现象 | 根因 |
|---|---|
| 场景存不住人物 | 应用的打开路径用 `cast_from_cards=True`，**用"本次装载的卡"覆盖场景自己的名单**；场景文件里的 `characters` 反而不被使用 |
| 没有人不能启动 | 打开路径的素材校验要求"至少一名角色"，空阵容被拒 |
| 后来加不进人 | 引擎只持有**构造期装载**的那几张卡（`cards` 字典），`add_character` 要求卡已在其中；库里其它卡**无法按需装载** |

**结论**：把「场景 → 人物」的关系从"每次现选"改为"**场景持有**"，并让引擎支持**按需从库里装卡**。

## 三、目标模型（落地口径）

### 3.1 场景持有阵容
- `Scene.characters` 是**唯一权威**：打开场景即使用它；空数组 = 合法的空场（无人活动，场景仍可开场、仍可推进/叙述）。
- 运行期的增删（添加角色 / 移出角色 / hooks 的角色事件 / 高级移入移出）**立即生效**，并**写回场景**（保存场景 / 自动保存 / 关闭时）。
- 调度器（think 扇出、bid 竞价、叙述）**只认当前在场且未禁言者**，随阵容更新实时变化；左栏冲动卡、右栏角色卡、在场人数等**同步增删**。

### 3.2 按需装卡
- 引擎获得**角色库目录**，`add_character(name)` 时若卡未装载则**从库里按名加载**（找不到则报错说明"库里没有这张卡"）。
- 因此任何库中角色都能在**任何时候**加入任何场景。

### 3.3 界面结构（只保留场景库）
- **顶栏**：设置 / 场景 / 角色。
  - 场景：打开场景（子菜单）、**配置场景**、保存场景、管理场景库…、新建场景、**导入场景**、重置场景运行上下文。
  - 角色：添加角色、移出角色、新建角色、**导入角色**、管理角色（当前阵容 + 卡片文件）、高级移入/移出。
- **场景库弹窗**（原「角色/场景库」改造）：只列场景，可 打开/编辑/复制/删除/新建/导入；**不再在这里选初始人物**——初始人物在**场景编辑器**里选。
- **启动**：不再弹开场设置窗；直接进主界面。
  - 未打开场景时：中间是**空状态页**，中央三个按钮：「打开场景」「新建场景」「新建角色」。
  - 打开场景后：正常对白界面。

### 3.4 配置场景
- 「配置场景」= 打开**当前场景**的场景编辑器（复用现有 `SceneEditorDialog`）。
- 保存后：写回场景文件；**并把可热更新的字段就地应用**到运行中的场景（名称/日期/背景/描述/可改变/剧情/边界），阵容变化则按增删处理；下次开场以文件为准。

### 3.5 场景变更可见
- 场景 agent 通过 tools / 场景事件改动了场景信息时，**在日志面板输出一条变更记录**（如「场景变更：描述 → …」），用**浅红色**高亮，与其他日志区分。
- 隐式（`visible=False`）的变更同样进日志（只是不进对话）。

### 3.6 视觉语言（科技感 · 简约 · 高级 · 无 AI 味）
原则：
1. **克制**：一个界面只用一到两个强调色；其余靠灰阶层级与留白区分。
2. **等宽/半等宽数字**：时间、token、数值用等宽感排版，读起来"像仪器"。
3. **少即是多**：去掉装饰性边框、阴影堆叠与彩色胶囊；用**细线 + 分隔**组织信息。
4. **无 AI 味**：**不用 emoji**（含日志里用作情绪标记的表情符号）、不用感叹号式文案、不用闪光 / 火箭一类的装饰符号；图标一律用文字或极简几何符号。
5. **深色优先**：默认主题给"科技感"版本（深灰蓝底 + 单一冷色强调），浅色主题为等价的干净版本。
6. **动效最小**：只保留必要的状态过渡，不做花哨动画。
7. **密度可控**：信息密集但留白到位；面板可滚动，永不挤压变形。

## 四、实施分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| **T1** | 引擎：按需装卡、场景阵容权威、空场可运行、阵容变更热更新调度与前端 | 任意库中角色可在任意时刻加入；空场可开场 |
| **T2** | 界面结构：去启动小窗 + 空状态页三按钮；场景库只保留场景；菜单加导入/配置场景 | 启动直达主界面；打开场景不再要求选人 |
| **T3** | 配置场景 + 状态保存（保存/自动保存写回阵容） | 改完场景立刻生效；重开保留阵容 |
| **T4** | 场景变更日志 + 浅红高亮 | 改名/改描述在日志可见 |
| **T5** | 视觉优化（配色/排版/去 emoji/图标/空状态） | 全局一致、无 AI 味、深浅两套均可用 |

1. 空场时是否允许"仅场景叙述"自动推进？当前口径：允许（场景仍可叙述与推进），但不产生角色台词。
2. 阵容变更的写盘时机：保存场景按钮、自动保存周期、以及**关闭/切换场景前**各一次。

## 六、第四批需求（撤回回溯 · 推进频率）

### 6.1 场景推进的撤回/改写要**回溯整段下文**
- **需求**：撤销或改写某条场景叙述时，**全文回溯到该推进节点**；此后**任何上下文**中都不得再出现被丢弃的那部分下文。
- **落地方案**：
  - `retract(id)` 语义改为**截断式撤回**：撤回该条**及其之后的所有消息**（同一场景内按 id 顺延）。
  - `edit_narration(id, text)` = 先回溯到该节点，再写入改写后的叙述。
  - 受影响面全部对齐：角色视图/锚点/动作去重/动态演化的 heard 取样（现已全部基于"未撤回消息"）；**think 只读日志**按轮次裁掉被回溯区间；**私有记忆**（`state.jsonl` 与印象）随轮次截断——为此给私有记忆条目加**轮次标记**，印象以 `(轮次, 文本)` 落盘（`.jsonl` 为准、`.md` 为人读渲染），撤回时按轮次截断并重写 md。
  - 界面：撤销/改写前给出明确确认（会丢弃其后的内容）。

### 6.2 自动推进的**频率可调**，且不再"有 hook 就每块都推"
- **需求**：场景推进频率可调（不用硬性数字写死）；并解释/修掉"某些场景发言频率格外高"。
- **根因（已定位）**：`_maybe_narrate` 中「有启用 hook → 每块都 `_narrate(consult_hooks=True)`」，**绕过判据与冷却**，因此凡带 hook 的场景每块都出一条叙述。
- **落地方案**：
  - **拆分两件事**：每块**咨询**场景（判 hook）≠ 每块**叙述**。咨询照旧每块进行；只有当场景真的给出了叙述正文（`parse_narration().text` 非空）时才落一条叙述消息——由场景自己决定"这轮要不要说话"。
  - 引擎侧判据（复读/停滞/临近边界）继续计算并作为**提示**喂给场景（说明"为什么现在叫你"）。
  - **活跃度**：新增 `narrate_activity ∈ [0,1]`（默认 0.5），统一缩放判据的触发线与冷却（活跃度越高 → 触发线越低、冷却越短），并作为语气提示写进场景提示词（"当前推进活跃度：低/中/高，请相应地少/多介入"）。
  - 设置持久化 + 左栏「场景推进」卡新增**活跃度**控件（少 / 中 / 多 / 极多），改后立即生效。
